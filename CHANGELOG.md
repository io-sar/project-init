## 0.6.0 · 2026-11-17
From hardening the trial project's settings.
- settings.json: secret files denied by name, so `.env.example` (variables without values) stays readable.
- Optional PreToolUse hook for Bash, proposed when Claude Code's sandbox is unavailable (e.g. native Windows): blocks shell commands mentioning `.env` files or `secrets.toml`, keeps `.env.example`, `.envrc`, `.venv` and `os.environ` working; documented as best effort (matches text, can be bypassed, fails open). Pattern verified on 12 cases; test scenario K added.

## 0.5.0 · 2026-11-17
From the first real run on an existing project (Streamlit app, hand-written CLAUDE.md, separate worktree). All runtime checks passed: CLAUDE.md only appended, 3 always-loaded rule files, path-scoped rules loaded on matching files, .env read blocked, formatter hook working on Windows.
- Questions: "None of these" is the first option of the context (Q7) and regulation (Q5) questions, so multi-select questions can always be answered; "installed at customers" moved to the hosting question.
- Hosting: new `paas` deployment value (managed platforms such as Streamlit Community Cloud, Heroku, Render, Vercel) with detection; Q10 asked whenever hosting is not detected, with 4 options. Infrastructure practices (IaC, container images, health endpoints, build once and promote, environment parity, graceful shutdown) no longer apply to managed platforms; twelve-factor, stateless tier and data residency still do.
- Selection reads `practices/TAGS.md` (one line per practice, generated by the validator) and then only the selected practices, instead of every group file.
- No repeats: rules whose intent already exists in the project's instructions are not written again (only additions); existing sections are judged by meaning, not heading.
- Decisions already documented in the project are linked instead of getting a new ADR.
- settings.json allows each routine command both bare and with arguments.
- New test scenario J (managed platform).

## 0.4.0 · 2026-11-17
Based on an independent review and the loading discussion.
- Loading: three tiers (always loaded, loaded by path, on demand in docs/standards/), a size budget (CLAUDE.md block under 120 lines, rule files under 250 lines), no Backlog in rule files, rule-text hygiene (no catalogue IDs, guide links or trade-off text in generated files).
- Milestones: the adoption plan (docs/standards-adoption.md) is grouped by milestone; upgrade mode moves a milestone's items into the rules.
- Questions: two rounds within the question tool's limits (max 4 questions per round, 4 options each, short headers); regulation options chosen from detection; Q7 adds "installed at customers" (on-prem); follow-up release question.
- Safety: proposed .claude/settings.json (deny secret files and force pushes, formatter hook); 15.3 and 15.4 became setup practices.
- CLAUDE.md: generated block between project-init markers, existing content preserved, AGENTS.md imported instead of duplicated.
- Conflicts: security and privacy one at a time; others in one table with KEEP CURRENT pre-selected.
- Tag grammar: has-any, NOT, note/opt-in/kind fields; tools/validate_catalogue.py checks every tag.
- Tensions: deterministic resolution order, auto vs advisory tensions, single ordered table T1-T21.
- Regulation: Cyber Resilience Act added (D9 value, practice 09.11); EU AI Act dates after Regulation (EU) 2026/1744 (09.8); GDPR/NIS2 deadlines, lawful basis per purpose, backups and erasure, EN 301 549 clarified; pci removed.
- New practice 10.8 security event logging; OWASP Top 10:2025 named in 08.2.
- Selection fixes: 04.1, 04.3, 04.4, 07.2, 09.4, 03.10, 11.10, 16.2; wording fixes: 01.4, 01.9, 02.3, 02.11, 04.16, 06.11, 13.2, 14.3, 14.7; duplicates reduced (03.2/15.6, 06.1/06.12, 14.6/14.8).
